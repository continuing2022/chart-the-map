# 决议：验证餐食营养估算方案

## Resolution

单张餐食照片不足以自动给出可信的热量和三大营养素；MVP 应采用“视觉识别候选 → 用户确认/修正菜品与份量 → 授权成分表确定性计算”的链路。

- 视觉模型只返回 1–3 个菜品/食材候选与置信度；通用识别 API 输出标签而非可审计的菜品份量与宏量营养素，例如 [AWS Rekognition DetectLabels](https://docs.aws.amazon.com/rekognition/latest/dg/labels-detect-labels-image.html)。
- 用户按菜品逐项新增、删除或修正，以少/标准/多表达份量；系统依据每 100g 的授权中国食物成分数据计算 kcal、蛋白质、脂肪、碳水。油、糖和酱汁必须可编辑。
- 保存用户确认的食材、份量、成分表版本及计算结果；修改后立即重算，保持历史结果可解释。
- 界面须明确“图片与份量推算，仅供饮食记录参考；不构成医疗、营养诊断或治疗建议”。深度、重量和完整配料能显著改善营养预测的研究事实可参见 [Nutrition5k](https://arxiv.org/abs/2103.03375)。
- 中国菜成分数据库的商业授权、更新频率与准确性尚需供应商/法务确认；真实餐食应按场景分层评测候选可确认率和用户修正率。
