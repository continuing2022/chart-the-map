# 腾讯云 POC 控制台准备清单

这是一份人工操作清单。请在自己的腾讯云控制台完成，绝不把密码、SecretId、SecretKey 或 API Key 发到聊天或提交到仓库。

## 1. 账户与预算

- [ ] 完成腾讯云账号实名认证及必要的计费开通。
- [ ] 在费用中心设置 100 元人民币的 POC 预算提醒；这只是测试止损线，不是产品用户额度。
- [ ] 确认混元图生图服务可在中国大陆地域使用，并阅读其当前计费、数据留存、训练使用和删除条款。

## 2. COS 私有存储

- [ ] 在与后端计划部署地一致的中国大陆地域创建一个 COS Bucket，例如 `meal-diary-poc`；地域以控制台中混元服务和后端实际可用地域为准。
- [ ] 设置为私有读写；关闭公共读、公共写和匿名列举。
- [ ] 为 POC 单独建立前缀：`poc/original/`、`poc/stylized/`、`poc/export/`；不要与将来的生产数据共用 Bucket 或前缀。
- [ ] 设置生命周期：POC 对象最长保留 7 天后自动删除；评审结束时手动立即清理。
- [ ] 不配置面向所有来源的 CORS；如未来小程序直传确有需要，只允许明确的小程序域名和最小方法集。

## 3. 最小权限与密钥安全

- [ ] 不使用主账号长期密钥。创建仅供 POC 后端使用的子账号或角色，权限限制到这个 Bucket、这些前缀和混元所需接口。
- [ ] 将密钥仅保存在本机安全的环境变量或受管密钥服务中；不要写入 `.env` 后提交，也不要放进小程序代码。
- [ ] 通过后端生成短时上传/下载授权；小程序不持有 COS 长期凭证。

## 4. POC 数据与操作

- [ ] 准备至少 30 张真实、已获使用许可且不含人脸、住址、车牌、聊天内容的餐食照片；上传前移除 EXIF/GPS。
- [ ] 为每张图分配匿名编号，例如 `P001`，并记录场景、风格、耗时、结果和评分，不记录身份信息。
- [ ] 原图先写入 COS 私有路径；由后端提交混元生成任务；结果可用后转存回 COS，再删除供应商短期结果链接和临时任务数据。
- [ ] 每次删除、替换或 POC 结束时，检查原图、风格图和任务记录是否同时清除。

## 完成标准

当以上清单完成、预算已设置、至少 30 张测试图已经准备好时，只需告诉我“腾讯云 POC 已就绪”。无需提供账号名或任何凭证；我将关闭准备卡并进入服务商选择与成本防护决策。
